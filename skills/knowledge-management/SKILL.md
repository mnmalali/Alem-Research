# Knowledge management

## Inputs

Approved project evidence, candidate claims, related wiki pages, and the knowledge-update workflow.

## Procedure

1. Search `knowledge/index.md` and linked pages before creating anything.
2. Classify each claim as verified evidence, reported finding, interpretation, hypothesis, or unverified.
3. Prepare a proposal listing new information, sources, page targets, wikilinks, and detected contradictions.
4. Reuse stable page identifiers; create a page only when no appropriate page exists.
5. Apply minimal additive edits, retain attribution, update `updated`, add backlinks, and preserve competing claims.
6. Update the index and changelog; review the Git diff before accepting.

## Output

Change proposal, updated pages/index, and changelog entry linking back to project evidence.

## Quality checks

- Every promoted factual claim has traceable support.
- No duplicate concept page was introduced.
- Conflicts are represented, not resolved silently.
- No project-sensitive material was promoted accidentally.
